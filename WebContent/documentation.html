1.1 MVC Architecture Explained in Basic Language

MVC ka matlab hota hai Model-View-Controller. Iska main purpose hota hai code ko clean, modular aur manageable rakhna. Aiye isko teen part mein todte hain:

1.2 Request-Response Execution Lifecycle

Jab student ya faculty browser par https://collegeerp-8jzy.onrender.com/login hit karta hai, toh piche kya kya step hote hain:

Complete Execution Pipeline:
1. Browser (Client): User URL click karta hai ya Form submit karta hai (HTTP POST / GET).
2. Cloud Server (Render Docker Container): Request Port 10000 par Tomcat 10.1 web server receive karta hai.
3. Servlet Engine (Jakarta EE 10): Tomcat URL pattern (e.g. /login) ko check karta hai aur LoginServlet.java ke doPost() method ko call karta hai.
4. Controller Validation: Servlet request.getParameter("username") aur request.getParameter("password") nikalta hai.
5. DAO Layer Execution: Servlet UserDAO.authenticate(username, password) method call karta hai.
6. Database Connection (DBConnection.java): JDBC Driver Railway Cloud MySQL (Port 17613) par TCP Connection establish karta hai.
7. SQL Query Execution: PreparedStatement SQL execute karke ResultSet return karta hai.
8. Model Creation: DB se aaye row ko User Java Object (Model) mein map kiya jata hai.
9. Session Binding: session.setAttribute("loggedUser", user) karke login state save hoti hai.
10. View Dispatching: response.sendRedirect("dashboard.jsp") ya request.getRequestDispatcher().forward() karke JSP screen render hoti hai.

UNIT 2: Technology Stack & Architectural Decisions

Iss section mein hum samjhenge ki humne Java 21 + Jakarta EE 10 (Tomcat 10) + MySQL 8.0 kyun chuna aur Spring Boot, Hibernate ya Frameworks ko bypass kyun kiya. Isse interviewers aur viva external ko answer dena bahut easy hoga.

2.1 Detailed Technology Stack Matrix

Technology Layer Chosen Tech / Version Why Chosen? (Technical Justification)
Programming Language Java 21 (LTS) Long-Term Support version, high security, fast execution speed, and backward compatibility.
Web Platform Specification Jakarta EE 10 (Servlet 6.0, JSP 3.1) Modern specification replacing old javax.servlet with jakarta.servlet for future-proof cloud architecture.
Application Server Apache Tomcat 10.1 (Temurin JDK 21) Lightweight, fast startup, low RAM consumption (ideal for Render free tier 512MB RAM), full support for Jakarta EE 10.
Database Engine MySQL 8.0 Community Server ACID compliant, robust foreign key constraints, high concurrency, and native JSON/Generated column support.
Database Driver MySQL Connector/J 8.3.0 Type-4 pure Java driver for maximum throughput and SSL/non-SSL cloud database connectivity.
UI & Styling Engine Vanilla CSS3 + Custom Glassmorphic System No heavy UI framework overhead (like Bootstrap/Tailwind), maximum CSS control, custom metallic gold + indigo palette.
Containerization Docker (Multi-stage Tomcat Base Image) Ensures "works on my machine, works on cloud" consistency. Eliminates environment mismatch bugs.
Cloud Hosting Render.com (Web App) + Railway.app (MySQL DB) Zero-cost cloud hosting architecture with automatic GitHub deployment pipelines.

2.2 Why Core Jakarta Servlets Over Spring Boot?

Viva mein sabse pehla question poochha jata hai: "Aapne Spring Boot kyun nahi use kiya?"
Answer:
  1. Deep Fundamental Mastery: Spring Boot aage chal kar servlets aur reflection ko hide kar deta hai. Core Servlets + JDBC se hume Request-Response, Thread Safety, Connection Pooling, aur Session Management ka exact working samajh aata hai.
  2. Lightweight Resource Footprint: Spring Boot app ka jar file 50MB-100MB ka hota hai aur boot hone mein 1GB RAM demand karta hai. Core Servlet app ka WAR size sirf 2MB-5MB hota hai aur sirf 150MB RAM par smooth chalta hai (Render free tier friendly).
  3. Zero Magic / Full Control: Code mein koi hidden annotations magic nahi hai. Jo SQL query humne PreparedStatement mein likhi hai, bilkul wahi execution database par hota hai.

4.1 Connection Manager (`DBConnection.java`) Complete Source

src/util/DBConnection.java
package util;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

/**
 * DBConnection — University of Lucknow ERP
 * 
 * Cloud-ready: reads DB config from environment variables.
 * Falls back to localhost defaults for local development.
 */
public class DBConnection {

    // Read from environment (Render / Railway injects these automatically)
    private static final String DB_HOST = getEnv("DB_HOST", "localhost");
    private static final String DB_PORT = getEnv("DB_PORT", "3306");
    private static final String DB_NAME = getEnv("DB_NAME", "college_erp");
    private static final String DB_USER = getEnv("DB_USER", "root");
    private static final String DB_PASS = getEnv("DB_PASS", "Manjeet@2007");

    // Support direct JDBC_URL if provided by cloud provider
    private static final String JDBC_URL_ENV = System.getenv("JDBC_URL");

    private static final String JDBC_URL = (JDBC_URL_ENV != null && !JDBC_URL_ENV.isEmpty())
            ? JDBC_URL_ENV
            : "jdbc:mysql://" + DB_HOST + ":" + DB_PORT + "/" + DB_NAME
              + "?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC"
              + "&useUnicode=true&characterEncoding=UTF-8";

    private static final String DRIVER = "com.mysql.cj.jdbc.Driver";

    static {
        try {
            Class.forName(DRIVER);
            System.out.println("[DBConnection] Driver loaded: " + DRIVER);
            System.out.println("[DBConnection] Host: " + DB_HOST + ":" + DB_PORT);
            System.out.println("[DBConnection] Schema: " + DB_NAME);
        } catch (ClassNotFoundException e) {
            System.err.println("[DBConnection] ❌ MySQL JDBC Driver NOT found!");
            e.printStackTrace();
        }
    }

    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(JDBC_URL, DB_USER, DB_PASS);
    }

    private static String getEnv(String key, String defaultVal) {
        String val = System.getenv(key);
        return (val != null && !val.trim().isEmpty()) ? val.trim() : defaultVal;
    }
}

UNIT 5: Data Access Objects (DAO) Codebase & Analysis

DAO Layer hamari application ka sabse crucial layer hai jo direct SQL Queries chala kar database transactions execute karta hai. Isme hum PreparedStatement use karte hain taaki SQL Injection Attacks 100% block ho sakein.

5.1 User Authentication DAO (`UserDAO.java`)

src/dao/UserDAO.java
package dao;

import model.User;
import util.DBConnection;
import java.sql.*;

public class UserDAO {

    public User authenticate(String username, String password, String role) {
        String sql = "SELECT * FROM users WHERE username = ? AND password = ? AND role = ?";
        try (Connection conn = DBConnection.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            
            ps.setString(1, username);
            ps.setString(2, password);
            ps.setString(3, role);

            try (ResultSet rs = ps.executeQuery()) {
                if (rs.next()) {
                    User u = new User();
                    u.setId(rs.getInt("id"));
                    u.setUsername(rs.getString("username"));
                    u.setPassword(rs.getString("password"));
                    u.setRole(rs.getString("role"));
                    u.setFullName(rs.getString("full_name"));
                    u.setEmail(rs.getString("email"));
                    u.setPhone(rs.getString("phone"));
                    return u;
                }
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
        return null;
    }
}

5.2 Marks DAO (`MarksDAO.java`)

src/dao/MarksDAO.java
package dao;

import model.Marks;
import util.DBConnection;
import java.sql.*;
import java.util.ArrayList;
import java.util.List;

public class MarksDAO {

    public void saveMarksBatch(List batch) {
        String sql = "INSERT INTO marks (student_id, subject_id, exam_type, marks_obtained, max_marks) VALUES (?, ?, ?, ?, ?)";
        try (Connection conn = DBConnection.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            
            conn.setAutoCommit(false); // Transaction management
            for (Marks m : batch) {
                ps.setInt(1, m.getStudentId());
                ps.setInt(2, m.getSubjectId());
                ps.setString(3, m.getExamType());
                ps.setDouble(4, m.getMarksObtained());
                ps.setDouble(5, m.getMaxMarks());
                ps.addBatch();
            }
            ps.executeBatch();
            conn.commit(); // Commit transaction atomically
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }

    public List getMarksheetByStudent(int studentId) {
        List list = new ArrayList<>();
        String sql = "SELECT m.*, sub.subject_code, sub.subject_name FROM marks m " +
                     "JOIN subjects sub ON m.subject_id = sub.id " +
                     "WHERE m.student_id = ? ORDER BY sub.subject_code ASC";
        try (Connection conn = DBConnection.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            
            ps.setInt(1, studentId);
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {
                    Marks m = new Marks();
                    m.setId(rs.getInt("id"));
                    m.setStudentId(rs.getInt("student_id"));
                    m.setSubjectId(rs.getInt("subject_id"));
                    m.setSubjectCode(rs.getString("subject_code"));
                    m.setSubjectName(rs.getString("subject_name"));
                    m.setExamType(rs.getString("exam_type"));
                    m.setMarksObtained(rs.getDouble("marks_obtained"));
                    m.setMaxMarks(rs.getDouble("max_marks"));
                    list.add(m);
                }
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
        return list;
    }
}

UNIT 6: Servlets & Controller Execution Pipeline

Servlets HTTP Requests handle karte hain. Tomcat jab request receive karta hai toh URL mapping ke basis par sahi Servlet execute hota hai.

6.1 Login Controller (`LoginServlet.java`)

src/servlet/LoginServlet.java
package servlet;

import dao.UserDAO;
import model.User;
import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.*;
import java.io.IOException;

@WebServlet("/login")
public class LoginServlet extends HttpServlet {
    private UserDAO userDAO;

    @Override
    public void init() {
        userDAO = new UserDAO();
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException {
        
        String username = request.getParameter("username");
        String password = request.getParameter("password");
        String role = request.getParameter("role");

        User user = userDAO.authenticate(username, password, role);

        if (user != null) {
            HttpSession session = request.getSession(true);
            session.setAttribute("loggedUser", user);
            response.sendRedirect("dashboard.jsp");
        } else {
            request.setAttribute("errorMessage", "Invalid Username, Password or Role selection!");
            request.getRequestDispatcher("login.jsp").forward(request, response);
        }
    }
}

UNIT 8: Master Viva & Interview Q&A Guide (50+ Questions)

Ye section viva external aur technical interviews ke liye sabse important hai. Isme top questions unke easy Hinglish answers ke saath diye gaye hain.

Top Viva Questions & Direct Answers

Q1: Servlet kya hota hai aur iska lifecycle kya hai?
Ans: Servlet ek Java class hoti hai jo server par request receive karke dynamic HTML response generate karti hai. Lifecycle mein 3 main methods hote hain: 1. init(): Servlet load hone par sirf ek baar chalta hai.
2. service() / doGet() / doPost(): Har client request par execute hota hai.
3. destroy(): Server shut down hone par memory release karta hai.

Q2: PreparedStatement aur Statement mein kya difference hai?
Ans: PreparedStatement pre-compiled hoti hai jisse execution fast hota hai aur ye ? (placeholders) use karke SQL Injection Attacks ko completely prevent karti hai. Statement mein raw String concatenation hota hai jo insecure hai.

Q3: Aapne Render par Tomcat ka port 8080 se 10000 kyun change kiya?
Ans: Render.com Docker containers ke liye default Port 10000 bind karta hai. If Tomcat 8080 par listen karega toh Render ka reverse proxy connect nahi kar pata aur 404/502 Gateway Error aata hai. Isliye server.xml mein port 10000 configure kiya gaya.

Q4: Marksheet aur Fee Ledger print layout bina navbar ke kaise print hota hai?
Ans: Humne CSS mein @media print block likha hai. Jab user Ctrl+P karta hai, tab .sidebar aur .top-navbar elements ko display: none !important; kar diya jata hai aur A4 sizing apply ho jati hai.
